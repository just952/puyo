   PNG 나 GIF 파일로 이미지로 꾸미고 싶다. 한글도 이미지가 아닌 폰트로 표시되게 하고 싶고.
   플레이는 기본은 컴퓨터와 1인 플레이, 같은 네트워크상의 유저와 2인 게임이 가능하게 하고 나중에는

✦ 자바로 1990년대 레트로 스타일의 뿌요뿌요(Puyo Puyo) 클론 코딩을 기획하고 계시는군요. 스탠드얼론 실행,
  리소스(이미지/사운드) 활용, 폰트 렌더링, 그리고 확장 가능한 네트워크 아키텍처까지 고려한 기술 스택과 구조적
  제안을 정리해 드립니다.

  ---

  1. 그래픽 및 GUI 렌더링 기술

  스탠드얼론 실행(의존성 최소화 및 단일 JAR 배포)과 90년대 2D 픽셀 아트 그래픽을 효과적으로 표현하기 위한
  선택지입니다.

   * 추천: Java Swing (javax.swing 및 java.awt)
       * 이유: JDK 기본 내장 라이브러리로, 별도의 외부 라이브러리 설치 없이 실행 가능한 단일 가벼운 JAR 파일을
         만들기 가장 좋습니다.
       * 구현 방식: JFrame 위에 커스텀 JPanel을 얹고, paintComponent(Graphics g)를 오버라이드하여 더블
         버퍼링(Double Buffering) 방식으로 화면을 직접 드로잉합니다. 60FPS 단위로 화면을 강제
         갱신(Repaint)하도록 설계합니다.
   * 이미지 처리 (BufferedImage):
       * javax.imageio.ImageIO를 사용하여 PNG(반투명/알파 채널 지원) 및 GIF 이미지 리소스를 불러옵니다.
       * 스프라이트 시트(Sprite Sheet) 기법을 사용해 하나의 큰 PNG 파일에서 뿌요들의 회전 애니메이션, 터지는
         이펙트 프레임을 getSubimage()로 잘라내어 렌더링 효율을 극대화합니다.
   * 폰트 처리 (한글 폰트 적용):
       * 사용자 PC에 설치된 폰트에 의존하지 않고, 레트로 감성의 둥근모(Neodgm)나 픽셀 스타일의 한국어 TTF/OTF
         파일을 프로젝트 리소스 폴더에 내장시킵니다.
       * java.awt.Font.createFont(Font.TRUETYPE_FONT, stream)를 통해 실행 시점에 폰트를 동적으로 로드하고
         Graphics2D.setFont()로 적용하여 일관된 화면을 보장합니다.

  2. 게임 루프 (Game Loop) 구성

  실시간 퍼즐 게임에서는 프레임 저하나 입력 지연 없이 부드럽게 작동하는 게임 루프가 필수적입니다.

   * 스레드 기반 전용 루프:
       * Runnable을 구현한 별도의 게임 스레드를 생성하여 "Fixed Timestep, Variable Rendering" 패턴을
         적용합니다.
       * 물리 연산/입력 처리(Tick)와 화면 그리기(Render)를 분리하여 시스템 성능에 관계없이 일정한 속도로 뿌요가
         떨어지고 연쇄 반응이 계산되도록 제어합니다.

  ---

  3. 통신 및 대기실 확장 가능 아키텍처 (가장 중요한 부분)

  1인용, P2P 2인용, 그리고 추후 대기실/매칭 서버 전환까지 고려한 확장성 있는 설계가 필요합니다.

   * 통신 프로토콜: TCP (Socket)
       * 실시간성이 요구되지만, 뿌요의 위치 정보, 블록 상태, 연쇄 및 방해 뿌요(Garbage) 전송 등은 단 하나의
         패킷 유실도 허용되지 않는 완벽한 동기화가 필요하므로 UDP보다 TCP 소켓 통신이 적합합니다.
   * 통신 레이어 추상화 (Interface-Driven Design):
       * NetworkHandler 인터페이스를 정의하여 게임 코어 로직과 네트워크 통신 구현체를 격리합니다.
       * 이벤트 기반 메시지 브로커 패턴: 클라이언트의 행동(뿌요 이동, 회전, 배치 완료, 연쇄 발생)을 직렬화
         가능한 DTO(Data Transfer Object)나 JSON 형태의 프로토콜 패킷으로 정의합니다.
       * 확장 로드맵:
           1. 로컬/AI 싱글 플레이: LocalGameLoop가 패킷 교환 없이 내부 메모리 상에서 직접 상대방(AI) 세션을
              갱신합니다.
           2. LAN 2인용 (P2P): 한 명이 방장(Host)이 되어 ServerSocket을 열고, 다른 한 명이 Socket으로 직접
              연결하여 1:1로 패킷을 직접 송수신합니다.
           3. 대기실/매칭 서버 도입 (추후 확장): 게임 클라이언트는 중앙 매칭 서버에 상시 TCP 소켓 혹은
              WebSocket으로 연결되어 대기합니다. 매칭이 성사되면 서버가 중계(Relay) 역할을 하거나 세션을 매핑해
              주어 동일한 패킷 인터페이스를 그대로 사용해 플레이하도록 만듭니다.

  4. 사운드 및 오디오 엔진

   * 오디오 API (javax.sound.sampled):
       * 외부 무거운 라이브러리 없이 JDK 표준 API를 활용합니다.
       * 효과음 (SFX): 뿌요 회전, 충돌, 터지는 연쇄음 등 짧은 오디오는 .wav 형식으로 인메모리에 로드해 두는
         Clip 객체를 사용하여 지연 시간(Latency) 없이 재생합니다.
       * 배경음악 (BGM): 용량이 큰 배경음악은 스트리밍 방식으로 재생(SourceDataLine 사용)하거나, 90년대 감성을
         위해 자바 내장 미디 시퀀서(javax.sound.midi)를 사용하여 가볍게 .mid 음악을 재생하는 것도 훌륭한
         대안입니다.

  5. 컴퓨터 대전 (AI) 구현 기술

   * 휴리스틱 기반 그리디 AI (Heuristic-based Greedy AI):
       * 복잡한 딥러닝 없이도 훌륭한 난이도를 구현할 수 있습니다.
       * 현재 나오는 뿌요 쌍의 색상 조합에 대해 6개 열(Column)과 4개 회전 방향에 따른 모든 배치 가능 경우의
         수(최대 24가지)를 가상으로 시뮬레이션합니다.
       * 가치 평가 함수(Scoring Function):
           * 연쇄가 가능한 링크 수(같은 색 인접 상태)가 많을수록 높은 점수.
           * 가운데 열(특히 3번째 죽는 칸)이 막히지 않도록 높이가 낮을수록 높은 점수.
           * 색상이 수직/수평으로 조화롭게 뭉치도록 유도하는 가중치 부여.
       * 이를 통해 초급/중급 수준의 성능 좋은 90년대식 인공지능을 가볍게 구현할 수 있습니다.

  요약 및 개발 로드맵 제안

   1. Phase 1 (싱글 핵심 로직): Swing으로 창을 띄우고, 폰트/스프라이트 이미지를 로드하여 1인 플레이(낙하, 조작,
      충돌, 연쇄 판정, 방해 뿌요 로직)를 로컬에서 완벽하게 구현합니다.
   2. Phase 2 (사운드 및 AI 추가): 효과음/배경음 재생 기능을 얹고, 가벼운 알고리즘 기반의 컴퓨터(AI) 상대를
      추가하여 1인 플레이 모드를 완성합니다.
   3. Phase 3 (네트워크 추상화 및 P2P 개발): 통신 인터페이스를 설계하여 1대의 PC에서 LAN 상의 다른 PC와 직접
      1:1 대전이 가능한 모드를 구축합니다.
   4. Phase 4 (대기실 서버 구축): 별도의 가벼운 자바 스프링/네티(Netty) 기반 서버 혹은 간단한 소켓 서버를
      빌드하여 유저 매칭 및 로비 시스템으로 확장합니다.

  이 기술 검토안에 대해 어떻게 생각하시나요? 먼저 Phase 1의 게임 화면 구성 및 로컬 1인용 프로토타입 구현을 위한
  프로젝트 설계를 시작해 볼까요? 의견을 주시면 그에 맞게 안내해 드리겠습니다.
